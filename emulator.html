The emulator

The watch,
before the watch.

Every interaction gets tested here first, in pixels, where changing your mind costs nothing. This is the Essential Watch OS running today, a 128 by 64 monochrome panel driven by the same mode machine the firmware will use.

Hold any key or button for half a second for a long press. From the watch face, a long press of the crown opens the menu.

What is simulated The game loop, the mode state machine, simulated heart rate and heading, piezo-style beeps and chimes, and every gesture: click, double press, long press, rotation. What is not simulated yet: the mode cycle from the v6 spec, BLE notifications, and real sensor behaviour. The screen runs a 128 by 64 monochrome panel at 30 frames per second.
Under the hood

Close to the pixel buffer.

No framework, by conviction. A firmware simulation wants the same shape as firmware, so the emulator borrows the structure of an embedded GUI.

Kernel

WatchOS class

Holds the drivers: audio, graphics, simulated sensors, input feedback. Runs the frame loop and manages the active mode, the way a microcontroller loop() would.

Screens

Mode classes

Every screen inherits from one abstract Mode base: home, menu, stopwatch, timer, alarms, workout, compass, info. Adding a mode is copying a class and registering it.

Hardware

SimulatedSensors

Mock heart rate, battery, and heading today. On real hardware these become I2C readings, and the modes do not know the difference.
